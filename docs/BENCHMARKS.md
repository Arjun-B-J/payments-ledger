## Caveats

- One run per cell on a laptop, with Postgres and the load generator sharing the CPU. Treat differences under about 10% as noise.
- `synchronous_commit=off` and `fsync=off` are the embedded defaults: a commit never waits for the disk. On a durable production setup every commit waits for the WAL flush, which lengthens how long the hot row stays locked, so absolute numbers would be lower.
- The merchant has a lower account id than every user, so under lock ordering its row is locked first and held for the rest of the transaction.
